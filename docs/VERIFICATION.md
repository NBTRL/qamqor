# Проверка backend «Клуб волонтеров»

28 октября 2026 года. Проверялся проект C:/dev/qamqor2 по последнему backend-заданию. Web сохранен страницей-заглушкой; полноценный интерфейс и перенос главной не входят в этот этап.

## Повторный аудит и исправления

При повторной сверке с backend-промптом добавлены проверки, отсутствовавшие в первоначальном наборе из 65 тестов. Семь новых сценариев сначала воспроизвели ошибки; дополнительная конкурентная проверка выявила неверный код занятого e-mail. После исправлений проходят **78 тестов: 34 unit и 44 интеграционных**.

| Найденная проблема                                                                                                   | Исправление и проверка                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nullable-строки и числа описывались в OpenAPI как object; page/limit ссылались на Object, isPublic имел неверный тип | Явные примитивные типы DTO, корректные типы пагинации и фото; проверка всего OpenAPI и повторная генерация клиента                                                  |
| Завершившийся после анонимизации запрос мог заново сохранить анкету или комментарий                                  | Актуальный пользователь проверяется и блокируется в бизнес-транзакции до Trip/Event/ДОД; проверены устаревший Actor и настоящая параллельная запись/удаление        |
| Напоминание уже было в outbox, когда поездку перенесли, участник отменил запись или куратор потерял назначение       | Перед доставкой повторно проверяются даты, участие, состояние поездки/ДОД, публикация отчета и назначение куратора; устаревшее становится FAILED/REMINDER_OBSOLETE  |
| Ответ смены статуса заявки не содержал history, хотя Swagger обещал его                                              | Возвращается актуальная заявка с историей в том же транзакционном снимке                                                                                            |
| Logout очищал предварительную cookie ADMIN, но код оставался действительным                                          | Сервер инвалидирует соответствующий AdminLoginCode; повторный verify после logout отклоняется                                                                       |
| Повтор контакта после сбоя отправки кнопок ломал Telegram-вход                                                       | Повтор CONTACT_RECEIVED для того же владельца до срока безопасно возвращает ту же попытку без повторного перехода; удаленный username очищается при следующем входе |
| При ошибке getMe/username/listen процесс мог остаться жив из-за Redis/BullMQ                                         | При неудачном старте вызывается app.close; unit-тест и запуск настоящего процесса на занятом порте подтверждают завершение с кодом 1                                |
| Превышение размера JSON или диапазона суммы могло давать 500                                                         | Единый VALIDATION_ERROR для некорректного тела и ошибок диапазона; сумма Donation ограничена Decimal(14,2)                                                          |
| Гонка подтверждения email давала CONFLICT вместо EMAIL_ALREADY_USED                                                  | Обработчик учитывает driverAdapterError.cause.constraint в Prisma 7; два одновременных подтверждения дают один 200 и один 409/EMAIL_ALREADY_USED                    |

Уточнения зафиксированы в CONTRACT.md. Изменений схемы БД не потребовалось; read-only migrate diff не обнаруживает расхождений. Основная база не сбрасывалась.

### Ключевые сценарии

- Два параллельных подтверждения последнего места: один успех, второй TRIP_FULL; CONFIRMED не превышает capacity.
- Отмена подтвержденного участника: старейший WAITLIST → PENDING с уведомлениями.
- Вход → онбординг → анкета → посещение ДОД → ACCEPTED/VOLUNTEER → запись → подтверждение → явка → DONE → отчет/REPORTED.
- Отдельно проверен порядок «сначала посещение ДОД, затем анкета».
- Чужой контакт, истекший token, пять неверных pollSecret, повтор USED, отказ «Нет», частота/бюджет опроса, блокировка аккаунта.
- Пять ошибочных admin-кодов, одноразовость, отказ предварительной сессии в доступе, запрет admin email backup.
- Смена подтвержденного email ADMIN отзывает старые сессии и незавершенные коды; просроченный резервный код не принимается.
- Кандидат и волонтер без завершенного онбординга не получают адрес учреждения; куратор не управляет чужим Place.
- Публичный календарь скрывает учреждение/сбор, публичные отчеты скрывают непубличные фото.
- Telegram 403 сохраняет причину и botBlockedAt, создает email fallback; 429 учитывает retry_after; после 5 попыток FAILED; IN_APP дедуплицируется.
- Перенос поездки делает старые напоминания недействительными; актуальное не дублируется.
- Настоящая очередь Redis/BullMQ передает DB-outbox воркеру, тот отправляет письмо в SMTP.
- Auth-mail содержит только зашифрованный конверт в Redis и пропускает заблокированного получателя.
- Все CMS CRUD проходят создание/чтение/изменение/удаление; неизвестные поля и неверные переходы отклоняются, скрипты/JS-атрибуты удаляются.
- Статистика принимает ручной ноль, новое значение и возврат к расчету через null.
- MinIO отклоняет неверные размер/MIME, сервер отклоняет поддельную сигнатуру; приватное фото закрыто гостю до явной публикации.
- Удаление загрузившего фото аккаунта убирает ссылку даже из отчета другого автора, сохраняя сам отчет.
- Повторный seed не создает дубликаты и сохраняет отредактированные записи; телефон/согласие администратора не подделываются.
- Моки grammY проверяют getMe/username, команды, polling/webhook, secret, request_contact и подтверждение устройства.

## Состояние локального окружения и границы проверки

Миграции применены к club, созданы 10 регионов, 8 демонстрационных учреждений, нужды и 2 сессии ДОД. ADMIN_TELEGRAM_ID/ADMIN_EMAIL не заданы: настоящий администратор и авторские демозаписи не создавались в основной базе; полный seed проверен на временной базе с синтетическим администратором.

Настоящий TELEGRAM_BOT_TOKEN не предоставлен. Работа HTTP-потока и обработчиков grammY проверена без обращения к реальному аккаунту Telegram. Реальный getMe/polling/webhook и доставка пользователю проверяются после настройки своего бота по README. Отсутствие bot token дает предусмотренный 503; production fake запрещен.

В HTTP-прогоне pg 8 выводит предупреждение об устаревающем параллельном client.query внутри Prisma adapter; проверки проходят. При обновлении pg до 9 потребуется сверить совместимость Prisma adapter.

Это проверка локального выполнения, не запуск production-инфраструктуры. Для деплоя нужны свои секреты/SMTP/S3/бот и размещение персональных данных на серверах России согласно требованию проекта.
