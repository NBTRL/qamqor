# Демонстрация учебного проекта Qamqor

Сайт: https://qamqor-tawny.vercel.app/. Все материалы с пометкой «Демо» вымышленные. Реальные мероприятия, поездки, сбор вещей и денег не организуются. Формы и записи сохраняются на сервере; Telegram-вход получает данные выбранного аккаунта. Для показа используйте отдельный тестовый аккаунт и вымышленные сведения в полях анкеты.

## Подготовка

Локально выполните установку, `docker compose up -d`, `pnpm db:deploy`, `pnpm dev` по README. Для публичной части администратор не нужен. Для полноценного показа ролей настройте своего администратора через `ADMIN_TELEGRAM_ID` и `ADMIN_EMAIL`, выполните `pnpm db:seed`, подключите собственного Telegram-бота и SMTP. Не запускайте локальный polling с ботом опубликованного сайта. Вход администратора требует Telegram и код из письма; обходного входа нет.

Миграция `20261030030000_educational_demo` добавляет отдельный набор:

| Материалы                          | Количество | Для чего нужны                                        |
| ---------------------------------- | ---------- | ----------------------------------------------------- |
| Учебный регион и вымышленный город | 1          | Фильтрация каталога                                   |
| Учреждения четырёх типов           | 4          | «Солнечный», «Горизонт», «Тёплый дом», «Добрый двор»  |
| Потребности                        | 12         | По три активные нужды в каждой карточке               |
| Публичные мероприятия              | 3          | Два доступны кандидату, одно — только волонтёру       |
| Поездка                            | 1          | Три места, запись волонтёра и подтверждение куратором |
| День открытых дверей               | 2          | Запись кандидата, отмена и повторная запись           |
| Новости                            | 2          | Маршрут демонстрации и описание ролей                 |

Даты создаются относительно первого применения миграции: ДОД через 5 и 12 дней, мероприятия через 7, 14 и 21 день, поездка через 28 дней. Начало — 09:00 UTC (12:00 МСК, текущая зона интерфейса). Повторный деплой не переносит события. Перед более поздним показом администратор меняет даты в интерфейсе. Для повторения записи на отменённое мероприятие используйте другую запись или аккаунт: повторная регистрация того же пользователя на тот же Event не предусмотрена; у ДОД повторная запись поддерживается.

## Маршрут показа на 5–7 минут

1. Открыть главную. Показать учебную отметку, новости и ближайшие события. Перейти в `/uchrezhdeniya`, отфильтровать «Учебный регион», открыть «Демо: детский дом „Солнечный“» и три нужды.
2. Открыть `/kalendar`. Выбрать «Демо: знакомство с Qamqor». Гость попадает на вход с возвратом к выбранному событию. Войти через Telegram, поделиться собственным контактом и заполнить обязательный профиль с согласием. После заполнения профиля сайт возвращает к выбранному событию. Такой же возврат работает у уже вошедшего пользователя с незавершённым профилем.
3. Записаться на событие. Открыть `/cabinet/registrations`: запись подтверждена. Отменить её и показать изменившийся статус. Попытка записи кандидата на «Демо: подготовка волонтёров» должна показать ограничение по роли.
4. Открыть `/stat-volonterom`, записаться на ДОД. Показать запись в кабинете, отменить и записаться повторно. Отправить учебную анкету кандидата. Не отмечать реальное посещение, которого не было: для демонстрации административной отметки используется именно учебная сессия.
5. При наличии настроенного администратора войти в отдельном профиле браузера. В `/admin/open-days` отметить учебное посещение, затем в `/admin/applications` принять заполненную заявку. Вернуться участником и обновить страницу: теперь ему доступна запись на поездку.
6. Администратором назначить этого волонтёра куратором «Солнечного» в `/admin/curators`. Открыть `/curator/trips`, участников учебной поездки и подтвердить запись. Показать разделение доступа: куратор управляет только закреплёнными учреждениями. Для листа ожидания нужны дополнительные тестовые участники и заполненные подтверждённые места.

Если Telegram или SMTP не настроены, показывайте публичную часть и явно укажите, что защищённые действия требуют подключения этих сервисов. Не включайте `DEV_FAKE_TELEGRAM` в production.

## Как устроено наполнение

Учебные материалы имеют отдельные slug `edu-*` и стабильные UUID `d30e0000-*`, не пересекаются с локальным seed `demo-*`. Автор контента — заблокированная обезличенная техническая запись с ролью CANDIDATE, без Telegram ID, e-mail, телефона, сессий и прав администратора. Пользоваться этой записью для входа нельзя; она нужна только для ссылок авторства. Учреждения не имеют реальных адресов и искусственного числа подопечных. Миграция не создаёт участников, регистрации, согласия, платежи или уведомления.

Добавление выполняется одним атомарным SQL-блоком. Конфликты по стабильным ключам пропускаются: правки, выключенные нужды, архивированные новости, перенесённые даты и существующие регистрации сохраняются. Для редактирования и скрытия используйте админку; миграцию повторно запускать не нужно. Удалять запись автора отдельно нельзя — на неё ссылается контент.

## Проверки

CI дополнительно проходит вход, профиль, запись и отмену настоящим браузером через API и отдельную временную PostgreSQL. Проверяются сохранение результата после перезагрузки, запрет кандидату административных действий и вход администратора с тестовым кодом из письма. Подробности и локальный запуск — в `docs/CI.md`.

`pnpm test:e2e` проверяет миграцию на отдельной локальной PostgreSQL: состав набора, отсутствие доступного аккаунта автора, повторное применение с сохранением правок и дат. HTTP-сценарий проходит каталог → нужды → публичный календарь → требование входа и онбординга → запись → кабинет → отмену, а также отказ кандидату в действиях волонтёра. Тестовая Telegram-подтверждающая точка используется только в изолированном test-окружении.

Компонентные и браузерные тесты проверяют ссылку календаря на вход с возвратом, сохранение выбранного события через обязательное заполнение профиля и серверную разметку без JavaScript. Внешние адреса и повторный переход на сам онбординг отклоняются; без выбранного назначения открывается кабинет. Полный вход в настоящем Telegram, письмо администратора и внешняя доставка уведомлений требуют ручного прогона с тестовыми аккаунтами; автоматические проверки их не подтверждают.
