# Хранение образов Qamqor

`scripts/registry-retention.mjs` работает только с `acme-5a14/qamqor`,
репозиториями `api` и `daemon.worker`. Используется официальный Vercel CLI
с его существующей авторизацией; токены в репозитории не хранятся.

Установите Vercel CLI 65.10.0 и задайте `VERCEL_CLI_ENTRY` — абсолютный путь
к `node_modules/vercel/dist/index.js`. Запуск без параметров показывает план:

```sh
node scripts/registry-retention.mjs
node scripts/registry-retention.mjs --apply
node --test scripts/registry-retention.test.mjs
```

Проверка выполняется перед созданием деплоя. Пока образов меньше 45, ничего
не удаляется. При 45 и более скрипт освобождает место до 30 образов при лимите 50.
Если безопасных кандидатов недостаточно, публикация блокируется.
Обязательно сохраняются:

- текущий production и предыдущий успешный production с другим коммитом;
- закреплённые версии `5409b6483fc8`, `31d83f43634c`, `79d8fe627a7d`;
- 10 последних образов и все образы младше суток;
- образы без тегов, с нестандартными тегами, незавершённые образы и OCI indexes.

Удаляются только готовые manifest-образы с тегами из 12 шестнадцатеричных
символов. Эти старые деплои после очистки могут стать недоступными;
поддерживаемый откат сохраняется. Перед каждым удалением повторно проверяются
production, откат, отсутствие активных сборок и актуальный список образов.
Если защищённый тег отсутствует, формат ответа неизвестен, идёт сборка или API
недоступен, скрипт прекращает работу. Если безопасных кандидатов недостаточно,
остаток может превышать 30: защитные правила важнее целевого количества.

## Публикация через GitHub Actions

`publish.yml` запускается после успешного `Project checks`. Деплой создаётся
через `scripts/publish-vercel.mjs` только после проверки обоих репозиториев.
Ветка main публикуется в production, открытые PR из NBTRL/qamqor — в preview.
Скрипты публикации всегда берутся из доверенной main; код PR с токеном не запускается.
Устаревшие коммиты и закрытые PR пропускаются. Общая блокировка сохраняется
до READY/ERROR, чтобы следующая публикация не очищала образы активной сборки.

В `vercel.json` отключены прямые Git-деплои: иначе они обходят проверку реестра.
Поэтому этот набор изменений нельзя объединять до настройки доступа CI.

Активация:

1. В GitHub NBTRL/qamqor → Settings → Secrets and variables → Actions добавить
   секрет `VERCEL_TOKEN` с доступом к acme-5a14, чтению проекта/деплоев,
   управлению образами VCR и созданию деплоев. Токен вводится владельцем напрямую
   в GitHub, не в чат и не в репозиторий.
2. После проверок объединить PR. Первый push main пройдёт CI и запустит публикацию
   через новый workflow. Production прежнего деплоя продолжает работать до READY.
3. Проверить workflow и новый деплой. Затем удалить прежнюю локальную автоматизацию
   Codex `qamqor`, чтобы она больше не проверяла реестр по расписанию.

Ручной `workflow_dispatch` выполняет только безопасную проверку без удаления
и публикации. Для локальной публикации используйте существующий вход CLI:

```sh
# Задать QAMQOR_DEPLOY_SHA (полные 40 символов), VERCEL_CLI_ENTRY,
# QAMQOR_DEPLOY_PRODUCTION=true для production, иначе preview.
node scripts/publish-vercel.mjs --dry-run
node scripts/publish-vercel.mjs
```

Кнопка Redeploy в Vercel и прямые сторонние API-вызовы обходят этот workflow.
Для гарантированной проверки ёмкости используйте настроенный процесс публикации.
Лимит веток Neon проверяется отдельно; очистка образов его не устраняет.
