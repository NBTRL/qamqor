# Информационные страницы учебного проекта

Qamqor — учебная демонстрация волонтёрской платформы. Для текущего учебного сценария не требуются данные реальной организации или банковские реквизиты. Статус проекта обозначен на каждой странице и в подвале.

Администратор может менять содержимое через раздел «Страницы» (`/admin/pages`). Поле slug должно совпадать с адресом:

| Адрес     | slug     | Демонстрационное содержимое                                         |
| --------- | -------- | ------------------------------------------------------------------- |
| /policy   | policy   | Описание того, какие данные используют учебные сценарии             |
| /kontakty | kontakty | Условный адрес и инструкция для тестирования обратной связи         |
| /donation | donation | Демонстрация раздела помощи без сбора денег и банковских реквизитов |

Миграция `20261030020000_educational_public_pages` создаёт отсутствующие записи. `ON CONFLICT (slug) DO NOTHING` сохраняет существующие документы и правки администратора. Повторное развёртывание не перезаписывает содержимое: уже применённую миграцию Prisma не запускает заново. Удаление записи оставляет краткое учебное описание на публичной странице.

Публичный frontend читает `/api/v1/pages/{slug}`. Текст проходит штатную серверную очистку HTML при сохранении в CMS. Если записи нет (404) или тело пустое, показывается краткое учебное описание; при недоступности API показывается ошибка загрузки. Обычное кеширование публичного API использует revalidate 60 секунд.

Учебный статус не превращает работающие интеграции в имитацию: подтверждённый Telegram-вход получает данные выбранного аккаунта, а обращения сохраняются на сервере. Для форм используются вымышленные имя, контакт и сообщение; для проверки Telegram можно использовать отдельный тестовый аккаунт. Условный адрес `qamqor@example.invalid` служит примером в интерфейсе, а не каналом доставки писем.

## Если проект будет адаптирован для реальной организации

Потребуются реальные сведения об операторе, утверждённый текст политики, публичные контакты и согласованный порядок помощи. Текст должен соответствовать используемой в формах версии согласия. Такая адаптация также требует пересмотра демонстрационных подписей сайта; это отдельная задача, не часть текущего учебного проекта.

## Публичные страницы без JavaScript

Основной текст, первая страница календаря и нужд, а также ссылки навигации доступны без JavaScript. В этом режиме показывается подсказка; формы, вход, запись и догрузка списков требуют JavaScript. Контактные поля заблокированы до подключения обработчиков формы, чтобы браузер не отправил введённые данные обычным GET-запросом.
